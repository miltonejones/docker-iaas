## Root Cause

The dark theme mechanism in `ThemeContext.tsx` applies a class (`dark-theme`) to the `<html>` element, but the CSS file (`styles.css`) contains **zero** `.dark-theme` CSS rules. All inputs (`input`, `select`, `textarea`) unconditionally get `border: 1px solid var(--border-strong)` from the base rule at line 1180-1187, regardless of theme. There's no dark-theme-specific override to remove those borders.

## Diagnosis

- `web/src/contexts/ThemeContext.tsx:13-18` — maps the `"dark"` theme to the CSS class `"dark-theme"` and applies it to `<html>` via `document.documentElement.classList.add(cls)` (line 37)
- `web/src/styles.css:1180-1187` — the base `input`/`select`/`textarea` rule has `border: 1px solid var(--border-strong)` with no theme-specific override anywhere in the file
- No `.dark-theme` selector exists anywhere in the 3867-line stylesheet, so there's no way for the dark theme to alter input styling

## Fix

Added a `.dark-theme input, .dark-theme select, .dark-theme textarea` rule after the existing focus rules (line 1204-1209) that sets `border-color: transparent`. This removes the visible border on form inputs when the dark theme is active, while preserving layout stability (using `border-color: transparent` instead of `border: none` avoids box-model shifts when switching themes).
