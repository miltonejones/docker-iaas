## Summary

### Root Cause
The Dockyard AI assistant had no way to persist accumulated conversation knowledge about resources to the `dockyard-knowledge` bucket. The system prompt already instructs the LLM to read from and offer to update this bucket, but there was no explicit UI affordance for users to save session context as markdown notes — the only way was through text-based assistant tool calls (`write_bucket_object`).

### Diagnosis
The feature was simply missing. The codebase already had:
- A `dockyard-knowledge` knowledge base pattern in the system prompt (keyed as `{type}/{id}.md`)
- A `bucketService.putObject()` function for writing bucket objects
- A `database` icon (`faDatabase`) in the icon registry
- A modal header row with Pin and Close buttons as a natural placement point

No endpoint, API client function, or UI button existed for syncing session knowledge directly.

### Changes Made

| File | Change |
|---|---|
| `server/src/routes/assistant.ts` | Added `POST /sync-knowledge` endpoint — accepts `{ log, resourceType, resourceId }`, formats log entries as markdown, creates the `dockyard-knowledge` bucket if needed, writes the note |
| `web/src/api.ts` | Added `assistantSyncKnowledge()` client function calling the new endpoint |
| `web/src/components/AssistantBar.tsx` | Added `resourceType`/`resourceId` props, `syncingKB` state, `syncToKnowledgeBase()` handler, and the "Sync KB" button in the modal header between Pin and Close (database icon, disabled while busy/syncing, shows "Saving…" during upload, only visible when `log.length > 0`) |

The button appears in the modal header row next to Pin/Close when the assistant has conversation entries. Clicking it sends the session log to the server, which writes it as markdown at `dockyard-knowledge/{type}/{id}.md`. While the request is in flight, the button shows "Saving…" and is disabled. On success, a confirmation entry appears in the conversation log.
