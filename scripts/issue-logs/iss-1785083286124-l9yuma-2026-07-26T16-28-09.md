## Diagnosis

**Root cause**: The toolbar's "Ask Dockyard" search input (`.assistant-search`) in `styles.css:208-229` uses hardcoded light colors:
```css
background: #eceef3;
border: 1px solid #d0d4de;
```

This is a `<label>` element (not a bare `<input>`), so the generic `.neon-theme input` rule in `neon.css` doesn't match it. The dark theme (`dark.css`) already had the fix — explicit `.dark-theme .assistant-search` and `.dark-theme .search-input` overrides that replace these colors with CSS variables (`var(--bg-elev-2)`, `var(--border-strong)`). But the neon theme (`neon.css`) was missing these same overrides entirely.

**Result**: In neon mode, the toolbar input appeared as a bright light-gray pill (`#eceef3`) floating on a near-black background (`#0a0a0a`), because the base stylesheet's hardcoded color was never overridden.

## Fix

Added 6 new rules to `/app/web/src/themes/neon.css` (matching the pattern already used in `dark.css`):

| Rule | Effect |
|------|--------|
| `.neon-theme .assistant-search` | Dark background (`var(--bg-elev-2)` = `#18181f`), subtle border, dark inset shadow |
| `.neon-theme .assistant-search:hover` | Neon green accent border on hover |
| `.neon-theme .assistant-search:focus-within` | Elevated background, accent border, neon green glow |
| `.neon-theme .search-input` | Same dark treatment for standalone pill inputs |
| `.neon-theme .search-input:hover` | Green accent on hover |
| `.neon-theme .search-input:focus` | Elevated background + green focus ring |

Because the rules use CSS variables, the neon green accent (`--accent: #00ff88`) is applied automatically — no neon-specific color values needed.
