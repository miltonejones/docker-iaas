## Response

The fix is clean and complete. Here's a summary:

---

### Diagnosis

**Root cause**: The `gateway` icon in `web/src/icons.tsx` was mapped to `faCircleNodes` — a network-topology icon (connected nodes/circles). Gateway list items (in both table and grid views in `GatewayPanel.tsx`) use `<AppIcon name="gateway" />`, which rendered this icon. The user wanted a **browser** icon instead.

### Fix

Changed the icon mapping in `web/src/icons.tsx:57`:

- **Before**: `gateway: faCircleNodes` — a network graph/topology icon
- **After**: `gateway: faGlobe` — a globe/world icon, which is the standard representation of a web browser/gateway

Also removed the now-unused `faCircleNodes` import from the FontAwesome imports.

### Impact

This change affects all uses of `<AppIcon name="gateway" />` across the app:
- **Gateway list table rows** (the primary target — each route row now shows a globe)
- **Gateway grid cards** (each card's header area now shows the globe)
- **Navigation sidebar** (service dropdown and bottom mobile tab bar)
- **Breadcrumbs** (when navigating gateway pages)

All of these consistently show the globe/browser icon now.
