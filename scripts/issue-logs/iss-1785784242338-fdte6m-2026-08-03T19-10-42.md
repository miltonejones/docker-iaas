## Summary

**Root cause:** The `Sync KB` button in `AssistantBar.tsx` was only rendered inside the `!embedded` (modal) header block. When the assistant is pinned to the workspace panel (`embedded={true}`), the entire Sync KB button was excluded from the header — only a "New" button was shown. This was an oversight: both modes should offer the Sync KB action when there's conversation content to save.

**What I changed:** In `web/src/components/AssistantBar.tsx`, I extended the `embedded` header section (the block that previously only contained the "New" button) to also include the Sync KB button, matching the same conditions and behavior as the modal view:

- Shows when `log.length > 0` (there is actual conversation to sync)
- Disabled while busy or while a sync is already in flight
- Displays "Sync KB" label or "Saving…" during the API call
- Same tooltip: "Save session knowledge to dockyard-knowledge bucket"

The `resourceType` and `resourceId` props (needed for resource-specific keying) are already declared in the component's Props interface and passed through to the `syncToKnowledgeBase` handler — the button works regardless of whether those are undefined (generic sync) or set to a specific resource.
